## Entregables
Two hygiene checks that today run only as local hooks (lefthook.yml) also run in CI on every pull request (finding of the W6 close, docs/plan/implementation/w0/README.md «Hallazgos de W6»). (1) Synthetic flag: a CI step runs `node tools/hygiene/synthetic-flag.mjs` over the checked-out tree (every JSON under FIXTURE_DIRS has top-level synthetic: true and no file there is ignored by git). Reuse the script as is; do not copy its rules. (2) Noreply: tools/hygiene/ci/noreply-range.mjs checks every non-merge commit of the PR range (`git rev-list --no-merges <base>..<head>`, base = origin/$BASE_REF as the owns-check step does): the author and the committer e-mail of each commit must be a GitHub noreply address (`<id>+<user>@users.noreply.github.com`, the NOREPLY_SUFFIX and emailOf of tools/hygiene/noreply.mjs) or exactly `noreply@github.com` (GitHub's own committer for web edits and merges). Output lists only the short SHA and which identity failed (author or committer), never the e-mail itself, names or commit messages. Exit 0 on pass, 1 on a violation, 2 on a git or usage error. (3) .github/workflows/ci.yml: two steps in the verify job next to owns-check (the noreply step only on pull_request; the synthetic step on pull_request and push), with the same pinned-SHA style and no new action or dependency; keep the header comment accurate (W7-02 is now in the editableBy of .github/). (4) The real-data denylist (tools/hygiene/denylist.mjs) CANNOT run in CI: its term list is private and lives only on the owner's machine, outside the repo. Do not add it, a placeholder list or a secret-backed variant; state this in a comment of the CI step block and in tools/hygiene/ci/README.md (short, Spanish).

## Criterios de aceptación (objetivos, verificables por pruebas o CI)
- [ ] tools/hygiene/ci/*.spec.ts builds throwaway git repos: a fixture JSON without synthetic: true makes the CI synthetic step's command exit 1, and the flagged fixture exits 0
- [ ] The same specs: a non-merge commit whose author or committer is not a noreply address makes noreply-range.mjs exit 1 naming only the short SHA and the identity; noreply@github.com as committer, <id>+<user>@users.noreply.github.com and merge commits pass
- [ ] Both checks exit 0 on the repository itself (a spec runs them on the current checkout, with base = the merge-base with main)
- [ ] ci.yml runs both steps (noreply only on pull_request) and the denylist is documented as local-only; actions stay SHA-pinned
- [ ] No e-mail address other than the two noreply forms appears in code, tests, output or docs
