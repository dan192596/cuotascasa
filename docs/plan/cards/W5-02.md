## Entregables
/app/prestamos/:id/tabla with an original/real/escenario toggle (active-scenario selector), sticky header, highlighted current row = currentInstallment from LoanProjectionService, 'Real Δ' column, yearly subtotal rows from the facade, keyboard navigation and cc-export-menu (frozen selector). In-cell abono per spec §9 «Abono en celda» and HU-17: (a) a new amount writes a hypothetical Prepayment to the ACTIVE SCENARIO with date = due date of row k, mode REDUCE_TERM and no commission; (b) if the active scenario already has a single Prepayment at k, the cell edits its amount keeping its id, mode and commission; (c) emptying the cell or typing 0 deletes that Prepayment with a tombstone; (d) the cell is read-only and points to «Proyecciones» when other hypothetical events exist at k (more than one prepayment, or an AdvanceInstallments); (e) with no active scenario the app OFFERS the loan's «Borrador» scenario (activate it, or create it if missing); on accept it saves there and announces it via aria-live, and if the user declines nothing is written. A cell is editable only when k > cutoffK ([ALG.PATHS.CUTOFF]); on confirm the table switches to the scenario view and never writes a real event. Rows with paid = true (ActualPayment) show the paid mark and, with a breakdown, Real Δ per component.

## Criterios de aceptación (objetivos, verificables por pruebas o CI)
- [ ] The toggle shows the matching path rows (component tests with facade fakes)
- [ ] Real Δ appears only on rows with a reported balance and equals reported - projected
- [ ] Yearly subtotal rows equal the facade's yearly subtotals exactly
- [ ] An in-cell edit creates or updates exactly one scenario Prepayment and changes zero real LoanEvents (store test); rows with k ≤ cutoffK reject editing
- [ ] e2e keyboard-only: navigate to an editable cell, type an abono, see the scenario end date change and the real-data count unchanged; axe clean
- [ ] A row k with an ActualPayment shows the paid mark (component test)
- [ ] With a breakdown, the row shows Real Δ per component = real − projected (component test)
- [ ] (a) A new in-cell amount creates a Prepayment in the active scenario with date = due date of row k, mode REDUCE_TERM and no commission (component test)
- [ ] (b) With a single existing scenario Prepayment at k, editing the cell changes its amount and keeps its id, mode and commission; no duplicate is created (component test)
- [ ] (c) Emptying the cell or typing 0 deletes that Prepayment with a tombstone (deletedAt set) (component test)
- [ ] (d) When other hypothetical events exist at k (two prepayments, or an AdvanceInstallments), the cell is read-only and points to «Proyecciones» (component test)
- [ ] (e) With no active scenario, «Borrador» is offered (activated if it exists, created otherwise); accepting writes the Prepayment there and announces it via aria-live; declining writes nothing (component test with a store spy)
- [ ] The highlighted row is LoanProjectionService.currentInstallment; with no current installment no row is highlighted (component test)
