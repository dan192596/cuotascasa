## Entregables
provideEngineFacade() implementing LoanProjectionService: maps entities to domain inputs and exposes memoized signals per loan: the three schedules (scenario = active scenario), metrics, yearly subtotals and the derived values defined in the spec §9 table (asOf = Clock.today(), currentInstallment, balance, percentPaid, nextInstallmentTotal, realEndDate, activeScenarioEndDate, validation status incl. 'UNVALIDATED', suggestedPaid) plus per-currency totals over active loans, and cutoffK, the per-row paid flags and realDelta per anchor and per component from buildPaths (the W0-05 LoanProjectionService list).

## Criterios de aceptación (objetivos, verificables por pruebas o CI)
- [ ] Every mapped field has a test, incl. END_OF_MONTH, fixed-charge effective dates and copied template values
- [ ] Signals recompute only when their inputs change (memo test)
- [ ] Totals are grouped by currency and never summed across GTQ and USD; the per-currency aggregation throws CurrencyMismatchError when handed a loan of another currency (test)
- [ ] Engine errors such as NegativeAmortization surface as typed state and are never thrown into templates
- [ ] A bench test recomputes 3 loans x 360 rows in < 100 ms
- [ ] Each spec §9 derived value is tested at its edges: asOf after the real end date gives no current installment and balance '0.00'; percentPaid rounds half up to 1 decimal and is clamped to 0-100; no ReportedBalance gives 'UNVALIDATED'; suggestedPaid is true when the latest ReportedBalance is '0.00' or asOf is after the real end date
- [ ] cutoffK, paid flags and realDelta per anchor and per component are exposed per loan and equal the domain buildPaths values (tests with an anchor, a late ActualPayment with breakdown and a real prepayment after an anchor)

## Notas
Tests use fake stores built from the data/api.ts interfaces, so this runs in parallel with W3-10/W3-11. Launch context (D27): an engine error caused only by the active scenario keeps every original and real value (paths with scenario = null; only activeScenarioEndDate, metrics().activeScenarioVsReal and yearlySubtotals().scenario are null); any other error nulls the nullable members, and the non-nullable ones keep their inert values. totalsByCurrency leaves out loans whose balance is null. compareScenarios puts a scenario whose events no longer compute in `failed`. Implement `checkRealWrite(loanId, write)` as a dry run over the real path with the write applied (never writes), with tests for a RateChange that triggers NegativeAmortizationError. toLoanTerms throws the domain's InvalidInputError for an invalid draft.
