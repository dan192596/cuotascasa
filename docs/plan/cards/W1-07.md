## Entregables
WebCrypto only. deriveKey(passphrase, salt, iterations = 600000): PBKDF2-SHA256 to an AES-256-GCM CryptoKey with extractable false. encrypt uses a random 96-bit IV and binds the envelope header as AAD. decrypt returns typed errors WrongPassphraseOrTamper, UnsupportedVersion, WeakParams and KeyMismatch (salt differs). Envelope v1 {format: 'cuotascasa-enc', v: 1, kdf: {name, iterations, salt}, cipher: {name, iv}, ct} with base64url fields. IndexedDB KeyStore persists the CryptoKey plus a salt id, never the passphrase. changePassphrase uses a new salt, re-derives and re-encrypts. The same envelope serves encrypted JSON export. Encrypted envelopes are generated in tests and never versioned.

## Criterios de aceptación (objetivos, verificables por pruebas o CI)
- [ ] Round-trip property for arbitrary UTF-8 payloads with a test-only reduced iteration count; a separate test asserts the production default is exactly 600000
- [ ] A wrong passphrase gives the typed error; flipping any byte of ct, iv, salt or header gives the typed error; no error message contains plaintext
- [ ] Envelopes with iterations < 600000 or an unknown v are rejected before any decryption attempt
- [ ] 10,000 encryptions produce 10,000 distinct 12-byte IVs
- [ ] The derived key has extractable === false, AES-GCM 256 and usages exactly ['encrypt','decrypt']; the KeyStore round-trip is verified in Vitest browser mode on Chromium and WebKit
- [ ] An IndexedDB content inspection test proves no passphrase or raw key bytes are persisted
- [ ] Test envelopes are generated at run time; no file with format 'cuotascasa-enc' is versioned (repo scan test)

## Notas
Opus implements this because an IV reuse, extractable key or KDF downgrade would expose financial data in a third-party cloud. A Sonnet reviewer cross-checks it against this list.
