## Entregables
Three tests fail without a product defect and block PRs (CI retries once; seen on #111 and #112, 2026-10-28). Fix the cause, keep what each test proves, and do not raise global timeouts or retries. (1) landing.spec.ts «the headline never scrambles»: it samples the h1 with textContent in a wall-clock loop of 800 ms and needs more than 5 samples; on WebKit in CI each read takes over 130 ms. Record every h1 text from the first parse instead: an init script with a MutationObserver on the document stores the h1 text on every mutation inside it, and the test reads the record once the page clock passes 800 ms after load. The assertion becomes: the record is not empty and holds only the final headline. (2) stubs-and-worker.sweep.spec.ts «one worker scoped to /…»: it loads seven /app routes with full page loads and only then waits for navigator.serviceWorker.ready. WebKit cancels a registration whose download a navigation interrupts (documented in core/pwa/provide-app-pwa.ts), so ready can hang until the 30 s timeout. Wait for ready (bounded) on the first /app page, then visit the other routes, then check registrations and the cache. (3) app.config.spec.ts «wraps navigations in a view transition, skipping only the initial one»: withViewTransitions keeps its skip-initial flag on the options object built once by appConfig, so the test only passes when it is the first router created in the worker (it fails inside the full ng test run). Export from app.config.ts a factory for the router's view-transition feature that appConfig uses, and test the behaviour on a fresh router built from it; keep one order-independent check that appConfig starts a transition on a later navigation.
