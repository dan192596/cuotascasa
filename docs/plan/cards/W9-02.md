## Entregables
Implement the W9-01 contracts. (1) Dexie and in-memory stores: markSynced clears only the pending entries covered by what was uploaded; an entry written later (newer updatedAt, or not uploaded) stays pending and lastSyncAt is still set. Add the case to the shared contract suite (packages/persistence/src/contract/) so both adapters and the reference fake prove it. (2) SyncSession passes what it uploaded to markSynced; session specs add an interleaved write between local.save and markSynced and assert the record is still pending and is uploaded by the next pass. (3) data/sync: after a session ends, pendingChanges is re-read, so the status never shows «Sincronizado» while a pending record exists. (4) provider.ts failureOf maps 403 storageQuotaExceeded to the new code and dailyLimitExceeded as W9-01 decided; settings-sync keeps the user connected on a full Drive (no «Conectar» loop) and shows the status text with what to do.

## Criterios de aceptación (objetivos, verificables por pruebas o CI)
- [ ] Contract suite: a record written after the uploaded snapshot is still counted by pendingChanges after markSynced, on Dexie (fake-indexeddb), memory and the reference fake
- [ ] Session spec with a delayed upload and a write in between: status ends with pendingChanges >= 1 and the next sync uploads the record
- [ ] Provider spec: 403 storageQuotaExceeded yields the new code, a 403 rate limit stays NetworkError, 401 stays AuthError
- [ ] settings-sync spec: with the quota code the component stays in connected mode, shows the full-Drive text and offers «Sincronizar» again, never «Conectar»
- [ ] Coverage of packages/persistence and packages/sync stays >= 95 %; pnpm lint && pnpm typecheck && pnpm test pass
