## Entregables
Opus card for seguridad-B1: a deleted record must not keep amounts, bank, notes or any other user field on the device indefinitely or in a backup. Decide and record in ADR-0005 and ADR-0008 (amendments) the shape, covering at least: (a) a tombstone stores only id, entity, loanId where the merge needs it, createdAt, updatedAt, updatedByDevice and deletedAt (entity schemas accept a tombstone variant; schema version and migration of existing tombstones on open and on backup import); (b) without Drive (lastSyncAt null) tombstones are purged by the ADR-0008 retention rule outside a sync, or immediately when the device never synced, whichever the ADR chooses with its reasoning about a later first connection; (c) the backup export carries tombstones only if the import needs them, and never their payload. Implement it across schema, both adapters, the contract suite and the merge (property tests keep LWW and deletion-wins-at-equal-timestamp results unchanged).

## Criterios de aceptación (objetivos, verificables por pruebas o CI)
- [ ] Contract suite: after remove(), reading the raw tombstone (adapter test hook) shows none of the entity's user fields, on Dexie and memory
- [ ] Migration test: a v1 dataset with full-payload tombstones opens and imports with the payload stripped; the backup schema accepts old files
- [ ] Purge test without Drive follows the amended ADR rule; merge property tests still pass
- [ ] Export test: a backup made after deleting a synthetic loan with a note contains no amount, bank or note of that loan
- [ ] Coverage >= 95 % in schema, persistence and sync; pnpm lint && pnpm typecheck && pnpm test pass
