## Entregables
provideBackup() implementing BackupService: exportJson plain or encrypted (cuotascasa-respaldo-YYYY-MM-DD.json); staged import parse -> migrate -> validate -> preview -> confirm -> snapshot -> replaceAll in one transaction -> undo token. Import keeps every record's stamps (createdAt, updatedAt, updatedByDevice, deletedAt) and never imports device-local Settings or deviceId; post-import counters follow ADR-0007 §6 and undo restores them. lastBackupAt; reminderDue signal per ADR-0007 (> 30 days since lastBackupAt or > 20 changesSinceBackup, incl. the null-lastBackupAt rule) as the single source of the reminder rule. Encrypted envelopes are generated in tests and never versioned.

## Criterios de aceptación (objetivos, verificables por pruebas o CI)
- [ ] Exporting and importing into an empty store yields an identical exportAll, ignoring exportedAt, deviceId and device-local Settings
- [ ] Invalid, foreign and future-version files return typed errors and leave the store untouched
- [ ] Undo restores the exact pre-import state; the snapshot is discarded after the next write or 10 minutes
- [ ] Encrypted export round-trips; a wrong passphrase gives a typed error; the encrypted Blob contains no plaintext alias; envelopes are generated in the test, never versioned
- [ ] reminderDue boundary tests at 20/21 changes and 30/31 days, both with a lastBackupAt and with lastBackupAt null
- [ ] Import keeps every record's stamps unchanged and never overwrites device-local Settings or deviceId (test)
- [ ] After import the counters match ADR-0007 §6; undo restores pendingChanges, changesSinceBackup and lastBackupAt exactly (test)
