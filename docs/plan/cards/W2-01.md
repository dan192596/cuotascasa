## Entregables
Only if the owner's explicit authorization (date and scope) is recorded in docs/specs/oracle-validation-log.md, Opus runs the oracle compare privately against the real bank table stored outside the repo; the validation log then records date, all rows matched (yes/no), mismatches 0, max diff '0.00' and the oracle commit SHA, with no amounts or terms. Without that authorization the log records 'validación privada: no autorizada' and the residual risk. Opus commits profile 'core' (~15 loans) plus tools/oracle/fixtures/manifest.json (profiles, seeds, counts, generatorVersion). CI gains: an oracle-diff job (Python from .python-version, pip install --require-hashes, regenerate only the profiles listed in manifest.json, git diff --exit-code; when code GENERATOR_VERSION is ahead of a profile's manifest generatorVersion it reports 'regeneration pending' for that profile instead of diffing) and a `pnpm conformance` job.

## Criterios de aceptación (objetivos, verificables por pruebas o CI)
- [ ] If the owner's explicit authorization (date and scope) is recorded in docs/specs/oracle-validation-log.md: private compare reports 0 mismatched rows, recorded as a log line without values; otherwise a line "validación privada: no autorizada" exists and the residual risk is recorded
- [ ] oracle-diff is green; editing one fixture value on a throwaway branch makes it fail; a profile present in code but absent from manifest.json does not affect it
- [ ] All fixtures pass the synthetic-flag and denylist hooks; gitleaks green
- [ ] `pnpm conformance` runs in CI and reports the core fixtures as pending (enforced set still [])
- [ ] The log line never includes the total row count or any loan term (test)
