## Entregables
After CI succeeds on main: build with --define GOOGLE_CLIENT_ID from a GitHub Actions variable (hashes in ngsw.json stay valid because nothing is mutated after the build), run edge:check locally, wrangler deploy with the CLOUDFLARE_API_TOKEN secret in a protected 'production' environment, then edge:check --base-url against the subdomain. Development builds keep an empty client ID.

## Criterios de aceptación (objetivos, verificables por pruebas o CI)
- [ ] A deploy run succeeds and the post-deploy edge:check against the live subdomain is green
- [ ] A repository grep finds no client ID value; development builds report Drive as 'no configurado'
- [ ] Deployed '/', '/privacidad', '/app/x' and '/nope' behave as ADR-0022 specifies (log attached)

## Notas
Owner prerequisites: Cloudflare API token, custom domain route, GitHub environment and variables. Deploying early surfaces production-only routing and header issues while the UI is small. Launch context (D27): also inject `--define REPOSITORY_ISSUES_URL="'<server_url>/<repository>/issues'"` from the Actions context, so the owner's username never lands in the repo; /privacidad needs the contact link (Google consent screen). Launch context (D29): ci.yml cancels in-progress runs on main, so a deploy-on-success skips cancelled commits; acceptable, or use `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`.
