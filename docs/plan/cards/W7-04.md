## Entregables
(1) data/device/provide-device-data.ts replaces Opus's inert stub (same export provideDeviceData; delete data/device/stub.spec.ts) with the DeviceDataService of data/api.ts: clearAll() disconnects Drive through SYNC_SERVICE when it is connected (the token is revoked), closes the DataStore (DATA_STORE of data-layer.tokens.ts), then deletes both IndexedDB databases of the app: the data store (DEXIE_DB_NAME of @cuotascasa/persistence/dexie, 'cuotascasa') and the key store (KEY_STORE_DATABASE of @cuotascasa/sync/crypto, 'cuotascasa-keys'), and resolves when both are gone. It never calls the Drive API except the revocation that disconnect() does; the Drive copy stays. A blocked or failed deletion rejects with DataError('STORAGE'). (2) features/settings/device/: a cc-settings-device component, hosted by settings-page.component.ts after cc-settings-sync, with a «Borrar datos de este dispositivo» section: what is erased (préstamos, datos reales, escenarios, ajustes de este dispositivo y la clave de cifrado guardada) and what is not (la copia en Google Drive, with the same steps as /privacidad: «Administrar aplicaciones» → CuotasCasa → «Borrar datos ocultos de la aplicación»); a destructive confirm that only enables the action after typing BORRAR (case-sensitive, trimmed), focus management and Escape to cancel. On success: a polite announcement through the root Announcer («Se borraron los datos de este dispositivo.») and then a full page load of /app (location.replace), because the in-memory stores are stale; /app then shows the empty dashboard. On failure: an assertive, fixed Spanish message and nothing else changes. (3) public/privacy/: the «Cómo borrar todos tus datos» paragraph adds «o con “Borrar datos de este dispositivo” en Ajustes» to the browser option, keeping every frozen heading and id of docs/specs/privacy-requirements.md and the zero-network, zero-storage rule of the public pages. (4) e2e/specs/sweeps/stubs-and-worker.sweep.spec.ts: remove the 'CC_STUB:W7-04' entry from PENDING_STUBS (leave the list empty and the mechanism in place). (5) e2e/specs/settings-device.spec.ts with the shared Google fakes (@cuotascasa/sync/testing): seed data and connect Drive, run the flow, then assert both databases are empty (absent, or recreated empty by the reload), the Drive fake still holds the same cuotascasa.json (and .prev) byte for byte, and the GIS fake lists the access token in revokedTokens.
