## Entregables
cc-event-form (frozen API) rendering a short Signal Forms form per type, each with an optional note: reported balance (date, installmentNumber optional, balance, totalInstallment?, reportedRate?, source), actual payment (paidDate, installmentNumber required, suggested from paidDate per [ALG.EVENTS.ANCHOR] and editable, total, optional breakdown), rate change (date, new rate, policy picker with a Spanish explanation per policy, bank installment for BANK_INSTALLMENT; on a FIXED loan a Spanish warning that still allows saving, [ALG.TERMS]), fixed charge change (the complete list effective from k, [ALG.FIXEDCHANGE]), real prepayment (amount, mode, commission) and advance installments (n). Field names come from the W0-04 schema entities, the single source (ActualPayment.paidDate, ReportedBalance.date, LoanEvent.date; optional note on ReportedBalance, ActualPayment and LoanEvent); where the spec words a field differently, the schema wins. Pure: takes loan context (disbursementDate, endDate, currency, rateType) and an optional existing DTO, emits a zod-valid DTO or cancel, never writes stores.

## Criterios de aceptación (objetivos, verificables por pruebas o CI)
- [ ] Component tests per type: valid input emits a DTO that parses with its schema entity; invalid input shows exact Spanish messages via aria-describedby
- [ ] Dates before disbursement or after loan end are rejected with a Spanish message
- [ ] Money fields use ui/money-input and never emit JS numbers
- [ ] The cc-event-form contract spec passes
- [ ] A RateChange on a FIXED loan shows a Spanish warning and still emits a valid DTO (component test)
- [ ] ActualPayment requires installmentNumber, prefilled from paidDate and editable; ReportedBalance emits a valid DTO without installmentNumber (component tests)
- [ ] Every form type emits its optional note field (component test)
- [ ] Emitted DTO keys match the W0-04 entity field names exactly (paidDate for ActualPayment, date for ReportedBalance and LoanEvent, optional note) (component test)
