## Entregables
(1) The dashboard loan card (active loans only) and «Datos reales» offer «Registrar el pago de este mes». It opens the real-payment form prefilled with the current installment: date = its due date, installment = k, amount = projected total, and the projected breakdown as editable suggestions (today initialModel leaves date and amount empty, event-form.logic.ts:113-120). The prefill travels in router navigation state, never in the URL or storage. (2) In «Datos reales», «Marcar cuotas pasadas como pagadas»: the user picks up to which past installment (default: the last one due before today), sees how many payments will be created, confirms, and each one is saved as a normal ActualPayment with the projected amounts. Installments that already have a payment are skipped. By [ALG.ACTUAL] this does not change the projection. If a failure mid-way would leave a partial set and data/api has no batch write, stop and ask Opus instead of improvising one.

## Criterios de aceptación (objetivos, verificables por pruebas o CI)
- [ ] Logic spec: the prefill for a synthetic loan equals the projected row of the current installment; nothing goes to the URL
- [ ] Bulk spec: marking up to k creates exactly the missing payments 1..k, skips existing ones, and announces the count politely
- [ ] Card spec: paid and archived loans do not show the button
- [ ] e2e (Chromium and WebKit): register this month's payment from the dashboard in two taps; axe without serious or critical issues
